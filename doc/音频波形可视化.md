# 音频波形可视化

## 2026-10-28：琶音显示频率波形

SW3 为 OFF、实际播放图片琶音时，显示绿色细曲线；SW3 为 ON 播放 PCM 时，显示原来的五格音量柱条。无需增加按键。启动时尚未显示图片的测试音继续使用柱条。

琶音曲线横轴固定表示约 5.33 毫秒：低音波峰疏，高音波峰密；同一音符调音量只改变高度，不改变疏密。图片琶音约 392～1047 Hz，可见约 2～6 个周期，切图时的 1500 Hz 短提示音约有 8 个周期。曲线取自音量调节后实际送往 HDMI 的样本，保留音源本身的阶梯正弦形状，不是 FFT，也不是根据音符名称绘制的模拟图形。

显示范围为 x=64～575、y=368～431。深蓝黑底 `101C28` 遮住该小区域内的图片，淡色中心线位于 y=400，绿色曲线 `40EFB0` 以两像素为基础宽度，陡处连接相邻高度，避免断线。没有额外峰值条或复杂网格。字幕区域不重叠；四格预览隐藏整个波形面板，仍继续采样。

每次等待音频由负值经过零点，再每两份样本记录一个端点，收集 128 段，总跨度为 256/48000 秒。固定触发位置减少同音符时曲线左右飘动；在相邻端点间画连接线，使高低音的周期都容易分辨。没有把每个音符拉伸成相同周期，也没有自动放大低音量。零音量或整帧没有音频样本时，在帧边界恢复水平线；音源切换会丢弃未完成的采集。换音时可能有一帧包含音符交界，下一次采集会跟上新音符。

实现与资源：

- `media_hdmi_audio_bridge.v` 输出与 HDMI 样本同拍的 `arpeggio_active` 标志，避免使用原始异步 SW3 电平判断当前音源。
- `promax_audio_waveform.v` 内增加 `arpeggio_scope` 模块，双缓冲保存 128 段相邻端点，每段 16 位，共 4096 位存储。单写口、同步单读口，不复位 RAM 数组，保留 BRAM 推断条件；实际 BRAM、LUT 和时序须由 TD 综合确认。
- 一块缓冲显示，另一块采集；完成采集后只在 VS 下降沿交换。音源显示样式也在帧边界锁存。沿用原有两拍视频流水，不改变 RGB／DE／坐标对齐、PCM 读卡或 48 kHz 音频节拍。
- 原有 32 点音量历史继续记录，PCM 仍按实际音量显示原来的五格柱条。

验证入口为 `tests/run_waveform_tests.ps1`（或 ModelSim 对应脚本）和 `tests/run_volume_tests.ps1`。新增 `tb_arpeggio_waveform` 检查 400／800／1600 Hz 的波峰疏密、实际采样端点、音量与截断、逐像素连接线、双缓冲帧内稳定、静音、音源切换和预览隐藏；音频桥回归额外核对音源标志与输出样本同拍。

本次上述 Icarus 波形及音量回归通过，包括原 PCM 柱条、640×480 视频／字幕／AXIS 链路；按实际 TD 工程源文件列表的顶层 RTL 展开通过，厂商加密 IP 按黑盒处理。新增单测还覆盖采集中途切换音源、预览隐藏时完成采集及返回显示。本次不运行 TD 综合或布局布线，不生成 bit，尚未上板验证。

## 屏幕效果与操作

- 正常显示图片后自动显示；自 2026-10-28 起，下述柱条用于 PCM，琶音使用上方说明的曲线。当前 SW3 选择 PCM／琶音，SW2 开启音量调节后 KEY2／KEY4 短按增减音量；KEY3 用于缩放模式中的预览操作。
- 横向 32 列，范围 `x=64～575`，每列间隔 16 像素，方块宽 12 像素，列间留空 4 像素。底边为 `y=431`，向上堆叠 1～5 层。
- 每个视频帧向左移一列，右侧加入最新平滑音量，约 60 Hz 下每列代表 16.7 ms，32 列保留约 0.53 秒，首尾时间差约 0.52 秒。上电时尚未记录的左侧区域显示底条。
- 每层高 4 像素，层间留空 4 像素；绿色主体为 `20EE70`，上边缘为黄绿色 `B8F438`。增加一格后实际最高图形占 `y=396～431`，底边和历史滚动速度保持原样。
- 去掉原中心线和右侧橙色峰值条。声音越强，叠起的小方块越多；声音减弱时缓慢降低，静音后保留一层底条。
- 柱条位于现有字幕背景区域 `y=438～461` 上方，两者不重叠。只有亮起的方块替换图片像素，柱间、层间和区域外保留完整 RGB888。
- 四格缩略图预览期间隐藏波形，仍持续采样，返回单图后显示近期音频。缩放模式中的单图仍显示波形。
- PCM 缺失、换音等待或缓冲欠载时，实际 HDMI 输出为零，右侧的新柱条按释放速度逐渐回落到底层，旧声音历史继续向左移出。若整帧没有样本脉冲，下一帧右侧直接补底条并清零包络；历史仍按时间移出，不会突然清空整排。

这里的“音量”指 FPGA 输出样本的幅度。文件内声音强弱和 SW2 模式下设定的音量都会影响图形；显示器自身的音量按钮不会把音量值传回 FPGA，因此不会改变图形。采用固定阈值分档，没有把每首音频自动归一化为最高柱条。各列代表相邻时间点的音量包络，不代表不同频段，不是 FFT 频谱。

## 与例程的对应关系

保留 32 个显示点及 VS 下降沿更新。之前每帧重采 32 点、`DECIMATE=24` 的版本只展示约 16 ms 音频，整排被替换，没有连续向左传播。当前移除该抽取参数，改为每个视频帧记录一次最新包络，使用 32 点环形历史。时间刻度由视频刷新率决定：约 60 Hz 时保留约半秒，最新样本至显示有正常的帧刷新延迟。讲义原先 `DECIMATE=12` 的 32 点窗口在 48 kHz 下仅约 8 ms，并非半秒。

每个有效音频样本先取绝对值，再更新平滑包络。上升采用 `ATTACK_SHIFT=8`（每次靠近目标约 1/256，时间常数约 5.3 ms），下降采用 `RELEASE_SHIFT=11`（约 1/2048，时间常数约 42.7 ms）。较快上升保留节拍响应，较慢回落和较低的显示高度让波形更柔和；整数步长向上取整，避免静音后残留非零包络。绝对值正确覆盖 `-32768`。

柱条固定阈值为包络 768、2304、6144、12288，分别增加到 2、3、4、5 层，低于 768 显示底层。2026-10-22 增加第五层，保留前四层门槛及平滑参数，用新一格显示更大的声音。持续等音量的音频会趋于稳定高度；不会人为制造与音量无关的跳动。

初版阈值为 4096／8192／16384，用户反馈大部分时间仅显示底层后，曾降低至 512／1536／4096，并将上升时间常数由约 10.7 ms 改为约 5.3 ms。随后用户反馈经常停在三层，本次将三档门槛统一提高 50% 至 768／2304／6144，上升保持约 5.3 ms，下降保持约 42.7 ms。此处只改变可视化灵敏度，不提高实际扬声器音量。本次继续只改源码和运行仿真，不执行布局布线、不更新位流，仍需重新构建并上板确认当前卡内音频的效果。

为适应现有工程作了以下处理：

1. 从 `media_hdmi_audio_bridge` 的 `audio_valid` 和 `audio_left_data[23:8]` 取样。这是音源选择、静音处理和音量增益之后，实际送到 HDMI 的 16 位有符号样本。采集和显示均使用 25 MHz 像素时钟，不增加跨时钟数据通路，也不改变 PCM 读取或 48 kHz 节拍。
2. 一个 32×8 位同步 RAM 保存历史包络高 8 位；写指针循环覆盖最旧值。仅在 VS 下降沿的垂直消隐期写入、推进指针，整帧有效画面期间 RAM 与指针保持不变，避免一帧中出现半新半旧的历史。有效计数屏蔽尚未写入的 RAM，无需复位整个数组；同步单写单读结构保留 BRAM 推断条件，实际资源需综合确认。
3. 包络使用所有有效音频样本持续更新，跨帧连续；与 VS 边界同拍的音频也纳入最新记录。按列从旧到新读取环形历史，最右侧为本帧提交的值。短促脉冲会被柔化；这是一项视觉平滑处理，不改变播放音量和声音本身。
4. 同步 RAM 读取和像素叠加分为两拍，RGB、VS、DE、坐标与帧起始一起延迟。随后进入字幕原有两拍流水线，最终交给 AXIS；有效区仍为每行 640 像素、每帧 480 行。
5. 顶层 `AUDIO_WAVEFORM_ENABLE=1` 默认开启，可在重新构建时设为 0 隐藏。模块默认位置保留例程的 `y=400`，实际顶层覆盖为 `y=368` 以避开字幕。
