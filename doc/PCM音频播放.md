# PCM 音频与图片琶音切换

## 2026-10-28：自动轮播背景音乐

当 SW3 选择 PCM，且自动轮播开启时，自动改为从头循环播放**播放列表第一张图片对应的 PCM**。普通播放下短按 KEY4 开关自动轮播（SW1、SW2 均关闭）；显示的图片仍按原轮播顺序前进。

- 第一张为 `PIC1.BMP` 时，播放 `AUDIO1.PCM`。若图片从 `PIC3.BMP` 开始，则第一张对应 `AUDIO3.PCM`；始终按图片编号匹配，不取根目录的第一个音频文件。
- 进入“PCM＋自动轮播”的组合状态时，从文件开头播放一次，之后持续循环。切换到下一张、最后一张回到第一张，以及该状态下的手动选图，均不换曲、不从头重播。
- 关闭自动轮播后，恢复当前实际显示图片的对应 PCM，并从头播放。
- 自动轮播期间拨 SW3 到琶音，继续使用当前图片的琶音；再拨回 PCM，则重新从头播放第一张的配音。没有开启自动轮播时，仅切换音源仍沿用原来的暂停／续播行为。
- 第一张缺少对应 PCM 时保持静音；文件无效时按原错误机制处理，不改播其他图片的音频或旧名称 `AUDIO.PCM`。
- 调音量、调亮度／对比度或缩放使轮播暂时停住时，只要自动轮播开关状态仍为开启，背景音乐仍选第一张。
- 配音字幕跟随实际选中的音频文件和样本计数，图片轮播不会重置背景音乐的字幕时间轴。现有字幕仅覆盖已内置的音轨；没有内置字幕的 AUDIO1 不会套用其他图片的讲解字幕。

实现新增 `media_pcm_selection.v`：在像素时钟域同步 PCM／自动轮播状态，独立生成 PCM 图片序号与换音事件。FAT 读取、HDMI 的音频确认和字幕时间轴均使用这个事件，图片提交事件继续用于显示和琶音。它只增加少量控制寄存器，不新增音频缓冲 RAM；切换背景音乐仍需等旧扇区结束、清空缓冲和填入新文件，因此进入／退出时可能短暂静音，后续轮播切图不会主动重启音频。SD 卡带宽不足导致的缓冲欠载仍按原机制处理。

验证入口：`tests/run_image_pcm_tests.ps1`。使用真实 FAT 扫描、文件读取、双时钟 PCM FIFO、Wipe 显示提交及 HDMI 音频桥，检查原逐图播放、自动轮播跨图连续样本／循环、进入退出、琶音切换、缺号列表、第一首缺失静音和旧扇区未完成时快速切换。项目已登记新模块；按此前要求，不运行布局布线、不生成新 bit，上板使用需要重新构建下载。

上述四组 PCM 回归全部通过（普通逐图、PIC1 起始轮播、PIC3 起始轮播、第一首缺失）。`tests/run_audio_tests.ps1` 的 48 kHz／ACR、四组共 24 个琶音音符及循环检查也通过；按实际工程源列表的顶层 RTL 展开通过，厂商 IP 按黑盒处理。尚未上板验证本次功能。

## 当前逐图配音规则（2026-10-20）

支持最多 16 个音频文件：`PIC1.BMP → AUDIO1.PCM`，依此类推到 `PIC16.BMP → AUDIO16.PCM`。按文件名数字匹配，不按屏幕播放序号匹配。例如只有 `PIC1.BMP`、`PIC5.BMP`、`PIC16.BMP` 时，第二张应搭配 `AUDIO5.PCM`。旧单文件 `AUDIO.PCM` 不再参与播放，也不作为备用音频。

图片实际提交到视频帧后，对应 PCM 从第一个样本开始循环；再次访问同一图片也从头播放。Wipe 转场从新图首次进入画面的那一帧开始换音。后台加载、按键请求尚未显示、交互缩放均不触发换音。换音期间先静音，等待旧扇区结束、双时钟缓冲清空和新样本预填充后开始播放，因此可能有短暂静音，不承诺无缝换曲。没有对应文件、空文件、奇数长度文件时，在 PCM 模式下静音，不能听到上一张的音频或自动回退的琶音。卡中存在无对应图片的音频不会加入图片播放列表。

KEY3 短按仍切换 PCM／琶音，上电默认琶音。仅切换音源而未换图时，PCM 暂停／续播原位置；在琶音模式下换图，则为新图片准备音频，切回 PCM 时从新文件开头播放。KEY3 长按仍进入／退出交互缩放模式。

## 音频准备

TF 卡使用 FAT32，根目录放置 `PIC1.BMP`～`PIC16.BMP` 和可选的 `AUDIO1.PCM`～`AUDIO16.PCM`。图片要求见 [多图片播放](多图片播放.md)。音频必须满足：

| 项目 | 要求 |
| --- | --- |
| 文件名 | `AUDIO1.PCM`～`AUDIO16.PCM`，8.3 短文件名，不加前导零 |
| 采样率 | 48000 Hz |
| 声道 | 单声道，HDMI 左右声道播放相同内容 |
| 样本 | 16 位有符号整数，小端序，低字节在前 |
| 文件内容 | 原始样本，不含 RIFF/WAV 文件头 |
| 文件长度 | 非零且为偶数；每秒 96000 字节 |

不能直接将 `.wav` 重命名为 `.PCM`。对于已经符合 48 kHz、mono、16-bit PCM 的 WAV，在工程目录执行：

```powershell
python doc/convert/wav_to_pcm.py input.wav AUDIO1.PCM
```

工具只去掉容器头、保留样本，不改变音量或重采样，不覆盖已存在的输出。其他格式可以先安装 FFmpeg，再执行：

```powershell
ffmpeg -n -i input.wav -vn -ac 1 -ar 48000 -c:a pcm_s16le -f s16le AUDIO1.PCM
```

完成后按对应 PIC 编号命名并复制到卡根目录，例如 `AUDIO1.PCM`、`AUDIO5.PCM`。当前扫描器沿根目录 FAT 链查找，最多扫描 1024 个根目录簇。文件数据本身可以分散在不同簇中，读取时跟随 FAT 链，不要求连续 LBA。插卡后按 KEY1 重新扫描。

当前 `sync_to_sd.py` 只更新 `PIC1.BMP`～`PIC16.BMP` 并删除同步数量之外的旧 PIC 文件，保留所有 PCM、其他文件和目录，不会清空目标盘或破坏 BMP 文件头。该脚本不会复制或自动重新匹配音频，重新排列图片后需自己检查配音编号。

## 按键与播放行为

| 板上按键及操作 | 代码端口／引脚 | 功能 |
| --- | --- | --- |
| KEY1 | `rst_n`／A2 | 系统复位 |
| KEY2 按下并松开 | `key1`／B2 | 切换下一张，未缓存图片按需加载，按住不重复切换 |
| KEY3 短按 | `key3`／B1 | PCM／图片琶音切换，消抖约 50 ms，每次按住只触发一次，不切图 |
| KEY4 短按并松开 | `key2`／C1 | 开关图片自动轮播 |
| KEY4 长按约 1 秒 | `key2`／C1 | 切换上一张图片 |

表中 KEY 编号按开发板实体按键标注；代码中的 `key1`、`key2` 分别对应板上 KEY2、KEY4。独立 KEY3 接线依据开发板例程的按键引脚表（A2、B2、B1、C1）。KEY2 长按不再切换音源，松开仍只切下一张。

当前按键补充（2026-10-20）：上表对应普通播放模式。KEY3 短按在松开时切换音源，长按进入／退出单图缩放；单图缩放中短按 KEY3 打开四格预览，预览中短按确认、长按取消，均不切换音源。要切换 PCM／琶音，请先返回普通播放。详见 [缩略图交互选择](缩略图交互选择.md)。

上电默认图片琶音；首张图片提交前仍为测试音。实际显示首图后即可为对应 PCM 预取数据，后续图片加载期间按扇区共享读卡。短按 KEY3 选择 PCM 后播放；没有匹配文件或还未填充时静音。后台预缓存下一张不打断当前音频；切图实际显示后重新选择配音。若卡响应过慢导致缓冲耗尽，暂时静音，数据到达后继续原位置。

从 PCM 切到琶音时暂停消耗 PCM 样本，SD 读入在缓冲达到水位后停止；未换图时切回来继续原位置，已换图则播放新图片的配音开头。琶音随当前显示图片选择，重新启用时重新开始提示音和旋律。

PCM 自动循环：正常读完当前 `AUDIOn.PCM` 后，从该文件首簇重新读取，下一轮样本接到上一轮之后，不自动切回琶音。换图从新文件开头播放；PCM 模式下没有文件或文件长度不合法时静音，不阻止图片显示。顶层 `AUDIO_PCM_ENABLE=0` 可关闭 PCM，`AUDIO_TEST_ONLY=1` 强制测试音并禁止读取 PCM。

## 实现与异常处理

`fat32_volume_scanner` 保存 16 槽音频首簇、大小及有效标记。`sd_fat32_image_source` 将实际显示的逻辑序号逐拍映射回 PIC 文件槽，再选择相同编号音频；参数锁存后才允许启动文件流。BMP 与 PCM 使用独立文件流，共用 SD 扇区通道，把音频字节交给 `pcm_stream_buffer`。后台读图期间继续补充 PCM，音频缓冲有整个扇区空间时优先补充。每次先授予访问权再发出请求，响应只送对应文件流。

换音事件直接来自像素域的视频实际提交信号，不使用后台加载编号或 Wipe 完成后才释放旧 bank 的 ACK。提交后 HDMI 立即屏蔽上一代 PCM；读卡侧等在途扇区结束再中止旧文件流。缓冲清空使用写域请求、读域确认的双向握手，两侧指针、有效位及残留半个样本一起清除。新文件准备好后回传提交代号，HDMI 只消费与当前图片匹配的 PCM。缓冲 RAM 数据本身不复位，使用独立同步读写端口以保留 BRAM 推断。

缓冲为 4096×16 bit（8 KiB），相当于约 85.3 ms 音频；256 样本预填充约 5.3 ms。一轮文件已读完时也允许开始播放，支持少于 256 个样本的短文件。双时钟指针带回卷位，在本时钟域生成 Gray 编码再同步。每次 SD 扇区请求前预留完整 512 字节空间，不在扇区中途反压。正常 EOF 仅重启同一文件流，不清缓冲；换图才清空缓冲。读取出错后停止循环，缓冲播空后保持静音。

HDMI 桥始终保持 48 kHz 样本节拍和原有 ACR；预填充或缺数据时输出静音，不重复旧样本。PCM 与琶音共用动态音量，默认 75%（192/256），SW2 开启后短按 KEY2／KEY4 增减 5%，支持 0% 静音和 100% 原幅度；音量信息经握手邮箱完整跨域，PCM 数据在像素域直接交给 HDMI。静音仍推进 PCM 和同步字幕，不是暂停。详见 [音量调节](音量调节.md)。

| 错误码 | 含义 |
| --- | --- |
| `71` | 空文件或奇数字节长度 |
| `72` | PCM 缓冲溢出保护 |
| `73` | 单次音频扇区读超时，默认 1 秒 |
| `23`～`26` | 沿用 FAT 簇链循环、越界、提前结束、访问上限错误 |

错误通过现有 UART／OSD 通道显示。读入出错后先播放已缓冲的完整样本，再静音并停止循环；实际换到另一张图片后重新选择文件并清除上一首错误，或按 KEY1 重新扫描。已读入的部分扇区不回滚。SD 底层不新增 CRC 校验。欠载记录在 `pcm_underflow` 内部输出，顶层未将它显示为错误码。正常循环时如下一轮未及时读到，则暂时静音并保持 PCM 模式。
