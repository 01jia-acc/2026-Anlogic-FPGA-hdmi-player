# PCM 音频与图片琶音切换

## 2026-10-12 工程备份说明

- 新增 FAT32 根目录 `AUDIO.PCM` 扫描与文件读取，支持 48 kHz、16 位有符号小端、单声道原始 PCM，并通过 HDMI 输出。
- 新增双时钟 PCM 缓冲及扇区水位反压，音频与图片共用现有 SD 读取通道。

- 修复 PCM 播放完毕后无法重播的问题：正常文件结束后从首簇继续循环，保持音频缓冲和播放状态；切换到琶音后暂停 PCM 样本消耗，切回继续播放。
- 补充 WAV 转 PCM 工具、中文使用说明、PCM 循环及按键回归测试，并同步构建后的 TD 下载位流，避免误用旧版本。

本实现依据《第十一讲：WAV音频播放》目录中的《第10课_WAV音频播放.md》，采用讲义要求的原始 PCM 格式。保留现有 FAT32、SDRAM 四 bank 图片预加载、按键切图和官方 HDMI 1.4b 发射核；没有照搬讲义中的原始 LBA 读取或替换 HDMI 核。

## 音频准备

TF 卡使用 FAT32，根目录放置 `PIC1.BMP`～`PIC4.BMP` 和可选的 `AUDIO.PCM`。图片格式要求不变。音频必须满足：

| 项目 | 要求 |
| --- | --- |
| 文件名 | `AUDIO.PCM`，8.3 短文件名 |
| 采样率 | 48000 Hz |
| 声道 | 单声道，HDMI 左右声道播放相同内容 |
| 样本 | 16 位有符号整数，小端序，低字节在前 |
| 文件内容 | 原始样本，不含 RIFF/WAV 文件头 |
| 文件长度 | 非零且为偶数；每秒 96000 字节 |

不能直接将 `.wav` 重命名为 `.PCM`。对于已经符合 48 kHz、mono、16-bit PCM 的 WAV，在工程目录执行：

```powershell
python doc/convert/wav_to_pcm.py input.wav AUDIO.PCM
```

工具只去掉容器头、保留样本，不改变音量或重采样，不覆盖已存在的输出。其他格式可以先安装 FFmpeg，再执行：

```powershell
ffmpeg -n -i input.wav -vn -ac 1 -ar 48000 -c:a pcm_s16le -f s16le AUDIO.PCM
```

完成后将 `AUDIO.PCM` 复制到卡根目录。当前扫描器只扫描根目录的第一个簇；建议使用整理过的卡并先复制这些媒体文件，避免大量旧目录项导致文件落到后续根目录簇。文件数据本身可以分散在不同簇中，读取时跟随 FAT 链，不要求连续 LBA。

已有的 `sync_to_sd.py` 会清空目标盘内容。若使用它同步图片，应先备份卡中数据、完成图片同步，再复制 `AUDIO.PCM`；不能把它当成无损追加工具。

## 按键与播放行为

| 板上按键及操作 | 代码端口／引脚 | 功能 |
| --- | --- | --- |
| KEY1 | `rst_n`／A2 | 系统复位 |
| KEY2 按下并松开 | `key1`／B2 | 切换下一张已加载图片，按住不重复切换 |
| KEY3 短按 | `key3`／B1 | PCM／图片琶音切换，消抖约 50 ms，每次按住只触发一次，不切图 |
| KEY4 短按并松开 | `key2`／C1 | 开关图片自动轮播 |
| KEY4 长按约 1 秒 | `key2`／C1 | 切换上一张图片 |

表中 KEY 编号按开发板实体按键标注；代码中的 `key1`、`key2` 分别对应板上 KEY2、KEY4。独立 KEY3 接线依据开发板例程的按键引脚表（A2、B2、B1、C1）。KEY2 长按不再切换音源，松开仍只切下一张。

上电默认选择原有图片琶音模式；首张图片提交前仍为测试音。图片预加载完成或停止后，开始为 PCM 预取数据。短按板上 KEY3 选择 PCM 后即可播放；预加载未结束时仍保留原有声音。播放期间仍能切换已缓存的图片。

从 PCM 切到琶音时暂停消耗 PCM 样本，SD 读入在缓冲达到水位后停止；切回来继续原播放位置。琶音随当前显示图片选择，重新启用时会重新开始提示音和旋律。

PCM 音频自动循环播放：每次正常读完 `AUDIO.PCM` 后，从文件首簇重新读取，下一轮样本接到上一轮之后。播放结束不会自动切回琶音，也不需要复位重播。KEY3 仍负责切换音源，切到琶音时暂停 PCM，切回时继续当前位置，包括跨越循环边界。没有文件或文件长度不合法时继续使用琶音，不阻止图片显示。顶层 `AUDIO_PCM_ENABLE=0` 可关闭 PCM，`AUDIO_TEST_ONLY=1` 强制测试音并禁止读取 PCM。

## 实现与异常处理

`fat32_volume_scanner` 单独记录音频首簇与大小。`sd_fat32_image_source` 在图片加载之后复用文件读取器和 SD 扇区通道，把音频字节交给 `pcm_stream_buffer`。BMP 解码器只接收图片事务的字节，不接收音频。

缓冲为 4096×16 bit（8 KiB），相当于约 85.3 ms 音频；256 样本预填充约 5.3 ms。一轮文件已读完时也允许开始播放，支持少于 256 个样本的短文件。双时钟读写指针带回卷位，在本时钟域生成 Gray 编码再同步。每次 SD 扇区请求之前预留完整 512 字节空间，不在扇区中途反压。正常文件结束仅重启文件读取器，保持缓冲、读写指针和 PCM 活动状态；发生错误时才发送缓冲结束信号，等缓冲和输出寄存器播空后退回琶音。

HDMI 桥始终保持 48 kHz 样本节拍和原有 ACR；预填充或缺数据时输出静音，不重复旧样本。PCM 同样经过 `AUDIO_VOLUME / 256` 增益，默认 192/256。按键模式信号同步到像素时钟域，PCM 数据在像素域直接交给 HDMI。

| 错误码 | 含义 |
| --- | --- |
| `71` | 空文件或奇数字节长度 |
| `72` | PCM 缓冲溢出保护 |
| `73` | 单次音频扇区读超时，默认 1 秒 |
| `23`～`26` | 沿用 FAT 簇链循环、越界、提前结束、访问上限错误 |

错误通过现有 UART／OSD 错误通道显示。读入出错后先播放已缓冲的完整样本，再退回原有音频并停止循环，复位后重新尝试；已读入的部分扇区不回滚。SD 底层仍沿用原实现，不新增 CRC 校验。缓冲欠载会记录在 `pcm_underflow` 内部输出上，顶层未将它显示为错误码；卡持续读取速度必须高于音频消耗速度。正常循环时如下一轮数据未及时读到，则暂时输出静音，保持 PCM 模式。
