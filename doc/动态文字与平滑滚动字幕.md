# 动态文字与平滑滚动字幕（2026-10-20）

参考 `D:\AnLu\完赛工程优化\第九讲：OSD字幕叠加` 的滚动原理、点阵字体和帧边界提交思路，接入现有图片播放器。讲义的 96 位短文本邮箱与少量固定汉字不能直接容纳整段文字，因此增加独立的双缓冲字幕 RAM 与生成字库。

## 实际显示效果

- 屏幕底部一行白色 16×16 点阵文字，字符等宽 16 像素，中英文均可显示。
- 字形位于 y=442～457；半透明深色底带 y=438～461，宽 640 像素。底带将背景 RGB 各通道减半，不需要颜色乘法器；带外像素保留 RGB888。
- 每帧向左移动 1 像素，约 60 像素／秒。从屏幕右侧进入，整段文字完全离开左边后，间隔 64 像素重新播放。90 字默认文本一轮约 36 秒；以实际视频帧率为准。
- 普通播放、切图转场和单图缩放时字幕持续播放，不因换图从头开始。进入缩略图时在下一字幕帧边界隐藏并暂停，退出后继续。
- 文本替换在帧边界生效，并从右侧重新开始。空文本关闭字幕，复位恢复默认文本；UART 更新只保存在易失 RAM 中。

默认段落保存在 `assets/subtitle.txt`：

> 欢迎使用 FPGA 图片播放器！支持图片切换、平滑转场、双线性缩放和缩略图选择。让每一张图片讲述一个故事，让文字随画面流动。串口发送一段文字并回车，即可更新滚动字幕。祝你学习愉快！

## 串口动态换文

仍使用板载串口 **115200、8N1**，接收与原有每秒诊断日志共存，不占用按键。

1. 串口助手选择 UTF-8 文本发送，关闭 HEX 发送。
2. 直接输入一整段文字，不需要 `SUB=` 等前缀。
3. 末尾发送回车 CR、换行 LF 或 CRLF，收到行结束后在下一帧整体替换。
4. 若要关闭字幕，单独发送一次空行；再次发送文字可重新打开。复位恢复默认段落。

例如发送 `图片播放器，欢迎你！` 加回车，或发送 `Hello FPGA! Image 09` 加回车。

一行最多 **256 个字符**，不是 256 个 UTF-8 字节。可打印 ASCII 包括大小写字母、数字、标点及空格；中文只支持已生成字库中的字符，字库外字符和不支持的 Unicode 字符显示 `?`。当前字库覆盖默认段落中 65 个非 ASCII 字符，以及 ASCII 32～126。不支持自动换行、多行排版、终端退格编辑、GBK 编码或 TF 卡字幕文件。建议发送 UTF-8 无 BOM 的单行文本。

超过 256 字或行尾 UTF-8 序列未完成时，整行拒绝，保留旧字幕；有效但无对应字形、非 BMP 字符（如 emoji）及非法编码序列会替换为问号。CRLF 作为一个提交处理。连续程序下发多段时，每段之间留至少 100ms，使帧边界提交和确认完成；等待确认期间收到的新行会整行丢弃，避免覆盖正在播放的 RAM。模块提供 `busy` 与 `rejected_lines` 调试输出，当前顶层未把它们加入串口日志，也未发送字幕 ACK 文本，因此不能依赖终端回显确认提交。

## 更改默认段落或扩充汉字

Python 脚本使用 Pillow 和本机宋体 `C:/Windows/Fonts/simsun.ttc` 生成 16×16 单色点阵。字体文件不复制到工程。生成出的 Verilog 已自带 ROM 初始化，无须 TD 在运行目录查找 `.mem` 文件。

在工程根目录执行：

```powershell
# 修改 assets/subtitle.txt，保存为 UTF-8 单行文本，然后生成：
python scripts/generate_subtitle_font.py

# 若希望串口还可显示其他汉字，先把所需文字放入 UTF-8 文件：
python scripts/generate_subtitle_font.py --extra D:/AnLu/额外字幕字符.txt

# 可选：另存字库图，检查实际点阵字形
python scripts/generate_subtitle_font.py --preview D:/AnLu/字幕字库预览.png
```

若未安装 Pillow，先执行 `python -m pip install pillow`。其他字体可通过 `--font` 指定，建议使用中文等宽字体。`--text` 可指定其他默认文本输入路径；默认段落必须为 1～256 字。脚本最多收录 **128 个不同的非 ASCII BMP 字符**（包括中文标点），超出时直接报错。多段将来要通过串口发送的文本，可一起放到 `--extra` 文件中生成所需字集。

生成结果为 `src/user_source/hdl_source/SD/subtitle_font.v`，必须重新生成位流后新字库才会进入 FPGA；仅串口替换内容且所有字符都已在字库中时不需要重编译。不要直接手改生成文件。

滚动速度通过顶层实例参数 `FRAME_DIV` 调整：默认 1 为每帧一步，2 为每两帧一步，3 为每三帧一步；每一步固定移动 1 像素。字幕位置通过 `TEXT_Y` 调整，循环间隔通过 `LOOP_GAP` 调整；参数应为正值且字幕区域应位于画面内。

## 代码与时钟域

`scrolling_subtitle.v` 在原有状态、时间戳、倍率和缩略图图层之后叠加字幕，随后送 `video_rgb_to_axis_640x480`。

| 时钟域 | 工作 |
| --- | --- |
| 50MHz `clk` | 使用现有 UART 接收器的字节，增量解码 UTF-8，将字形 ID 写入备用文本 bank |
| 25MHz `video_clk` | 帧边界接收整段文本，维护滚动位置，读取文字 RAM 和字库 ROM，混合像素 |

文本 RAM 为 512×8 位，包含两个 256 字符 bank。收到行结束才发布 bank 与 9 位长度；请求 toggle 经两级同步到像素域，在 `osd_frame_start` 提交，并返回 ACK。bank／长度从请求到 ACK 保持稳定；写侧在 ACK 前不允许再写，因此不会改坏当前读出的文本。无需给每个字符分别打两拍，也没有把 256 字的字符串用寄存器反复整体搬运。

读像素分为两级同步存储读取：第一级取得字形 ID，第二级取得对应点阵行。RGB、DE、VS 同步延迟 **两拍**，再一起接到 HDMI AXIS 转换器；前面的 reader 及 OSD 坐标、转场提交时序保持原有连接。输出只在有效笔画像素替换白色，底带使用移位变暗。

字库 ROM 为 4096×16 位（65536 位），文本 RAM 为 4096 位，不增加帧缓存、SDRAM 读取或 DSP 乘法器。常见 18K BRAM 容量估算约为字库四块、文本一块；实际 ROM／RAM 推断、BRAM 与 LUT／MSlice 数以 TD 综合报告为准。两个新 HDL 文件已加入 `.al` 工程列表。
