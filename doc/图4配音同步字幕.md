# 图4配音同步字幕

2026-10-22：采用用户选择的 SRT 分句同步。图4讲解为后母戊鼎介绍，共八句、215 字；每句以 16×16 字形在画面底部居中显示，句间留白，不再让整段连续滚动。

## 使用

1. TF 卡根目录保留 `PIC4.BMP` 和 `AUDIO4.PCM`，重新构建并下载本版位流。
2. SW3 拨至 ON 选择 PCM，切到图4即可听讲解、看同步字幕。SW4 控制缩放模式；KEY3 在缩放/预览内用于打开、确认与长按取消，不再切换音源。上电按实际开关位置生效。
3. 首句在音频播放约 0.25 秒后出现；整段音频 64.160875 秒，播放结束后音频与字幕一起循环。离开再进入图4从头开始。
4. 切回琶音时字幕隐藏、PCM 播放位置暂停，再回 PCM 继续。缩略图预览隐藏字幕，音频如继续播放，字幕时间也继续，退出预览显示当前句。
5. 其他图片仍支持串口滚动字幕。图4的文件字幕优先于串口，串口空行仅关闭串口字幕，不关闭图4配音字幕。

按真实文件数字匹配 `PIC4/AUDIO4`，即使图片缺号，也不会误将播放序号第四张当作图4。音频切换由显示提交触发，后台缓存预读不重启讲解。

## 同步与资源

`audio4_subtitle_timeline.v` 只在 `pcm_stream_ready && pcm_stream_valid` 时推进音频样本位置，以 48 kHz 将 SRT 毫秒换算成样本边界。因此 SD 预读、文件读取到 EOF 不会提前推进字幕，PCM 欠载插入静音期间不会累计相对配音的时间漂移。音频最后一个真实样本被消费后，字幕时间轴回到零。

每帧开始锁存当前句和长度，避免半帧换句；字幕画面相对 SRT 时间允许一个视频帧的刷新延迟。HDMI 显示器自身的音频/视频处理延迟仍需上板观察。

沿用原 256 字形、每字 16×16 的字库，容量仍为 65,536 bit；保留可打印 ASCII，将部分未使用控制码编号也用于汉字，支持至多 161 种额外字符，本讲解使用 137 种。复用原字幕字形 ROM 和两拍视频流水线，没有再加一份字库。生产配置中移除不再使用的开机段落 ROM；新增分句文字 ROM 为 256×8 bit，另有样本计数与句信息选择逻辑；实际 BRAM、MSlice 与时序以本版 TD 报告为准。

## 素材与再生成

- 卡上 PCM：48 kHz、16 bit 有符号小端、单声道、无文件头；6,159,444 字节，3,079,722 样本。
- PCM SHA256：`4a74c2d66e39b33be630f995da665ba26560c82e86cb1c963356d0a90b9c2e9b`。
- `assets/subtitle.txt` 保存卡上 TXT 全文；`assets/AUDIO4.srt` 保存卡上八段时间轴。TXT/SRT 目前编译进位流，板上无需解析它们。
- 本次只读取 TF 卡素材，没有修改卡上文件。PCM 不复制进 Git。

```powershell
python scripts/generate_subtitle_font.py
python scripts/generate_audio4_subtitle.py --pcm F:\AUDIO4.PCM
```

必须按上面顺序生成，以保证 SRT 文字编号与字库一致；更改音频长度时须同时更新生成脚本内 `total_samples` 和相应测试参考。脚本检查八段时间范围、重叠、最长 40 字及 SRT 拼接与 TXT 完全一致。
