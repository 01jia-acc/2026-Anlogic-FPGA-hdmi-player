# 多 BMP 图片播放

## 当前功能（2026-10-20）

图片资源当前限定为最多 **10 张**，识别 FAT32 卡根目录的 `PIC1.BMP`～`PIC10.BMP`。SDRAM 仍使用四个 bank 缓存：先加载前四张，随后后台补齐当前图片附近的四图窗口。保留 PCM 循环、图片琶音、手动切图和自动轮播。扫描器对外仍保留 16 位兼容接口，但高六位槽位不再使用。

这是有限的 10 张资源表，超过 `PIC10.BMP` 的文件不会加入播放列表。图片必须是 24 位、无压缩 BI_RGB、正高度的 BMP，宽度 1～1920、高度 1～1080，不支持 32 位或压缩 BMP。加载时使用双线性插值自动铺满 640×480；640×480 原图走直通路径。当前不保持宽高比，详见 [双线性图片缩放](双线性图片缩放.md)。

## 卡中内容与准备方法

卡使用 FAT32，文件直接放在根目录，例如：

```text
E:\
  PIC1.BMP
  PIC2.BMP
  ...
  PIC16.BMP
  AUDIO1.PCM      （可选，对应 PIC1.BMP）
  AUDIO2.PCM      （可选，对应 PIC2.BMP）
  ...
  AUDIO16.PCM     （可选，对应 PIC16.BMP）
```

按 PIC 文件名的数字顺序播放，允许缺号。例如存在 `PIC1.BMP`、`PIC5.BMP`、`PIC10.BMP`、`PIC16.BMP` 时，播放列表为这四张，屏幕序号显示为 01～04。根目录可以跨簇，扫描器沿 FAT 链扫描最多 1024 个根目录簇；媒体文件数据也可以分散在不同簇中，无需连续存储。

下面的既有工具会先在电脑上把图片转成 640×480，仍可正常使用。若要验证 FPGA 缩放，请另外准备保留原尺寸的 RGB24 BMP，按上述命名放卡；不经过这条预缩放流程。在工程根目录执行：

```powershell
python -m pip install Pillow
python doc/convert/convert_images_to_bmp.py
# 将图片放入 doc/convert/input_images，再执行一次转换
python doc/convert/convert_images_to_bmp.py
python doc/convert/sync_to_sd.py E:
```

请将 `E:` 改为实际 TF 卡盘符。同步默认最多 16 张，保留所有 PCM 和其他文件，只更新 `PIC1.BMP`～`PIC16.BMP`。源图片按文件名排序，推荐使用两位前缀固定顺序；PCM 请自行按转换后的 PIC 编号命名和复制，图片工具不负责匹配音频。同步后安全弹出卡，插入板卡并按 KEY1 复位。详细参数见 [转换工具说明](convert/README.md)，音频准备见 [PCM 音频播放](PCM音频播放.md)。

## 按键

| 实体按键 | 操作 | 功能 |
| --- | --- | --- |
| KEY1 | 按下 | 复位并重新扫描卡 |
| KEY2 | 按下再松开 | 下一张，末张回到首张 |
| KEY3 | 短按 | PCM／图片琶音切换 |
| KEY3 | 长按约 1 秒 | 进入／退出缩放模式，不切换音源 |
| KEY4 | 短按再松开 | 开启／关闭自动轮播 |
| KEY4 | 长按约 1 秒 | 上一张，首张回到末张 |

上表的切图与轮播操作适用于普通模式。缩放模式内，KEY2 松开增加倍率、KEY4 松开降低倍率，支持 0.5×、1×、1.5×、2×，长按这两个键也只在松开时调一档。缩小时居中留黑边，放大时居中裁剪，暂不支持平移。屏幕黄色 `ZOOM` 表示正在缩放模式，退出后非 1× 倍率仍以白字显示。缩放期间暂停轮播计时，退出后按原轮播开关重新计时；保留当前倍率，切换图片恢复 1×。KEY3 短按的音源切换改在松开时执行，避免长按进入缩放时误切音源。

加载端继续双线性缩放到标准帧，交互阶段对该标准帧作最近邻采样，具体原理和验证见 [双线性图片缩放](双线性图片缩放.md)。

2026-10-20 新增：单图缩放模式短按 KEY3 不再切换音源，而是打开四格缓存预览；KEY2／KEY4 向后／向前移动焦点，短按 KEY3 确认并以 1× 返回单图缩放，长按 KEY3 取消并保留原图原倍率。四格按播放顺序排列为前两张、当前张、后一张，首尾夹紧，少于四张时空槽不可确认；需要补读时先保留原图，补齐后进入。预览期间冻结新的图片加载，退出帧确认后恢复，避免后台覆盖正在显示的其他格子。详细说明见 [缩略图交互选择](缩略图交互选择.md)。普通播放模式的音源切换仍保留。

切到已缓存的图片无需再次读卡；切到未缓存的图片时，先保留旧画面，读取、解码并写入新的 bank，再在帧边界切换。文件读取和 SDRAM 整帧写入均完成后才允许显示，显示端返回确认后才允许复用旧 bank，以避免覆盖仍在显示的画面。

图片切换默认采用方案 B：**新图从上向下逐行覆盖旧图（Wipe）**。640×480 下共 16 个转场帧，每帧多显示新图的 30 行；第一帧上方 30 行为新图、下方 450 行仍为旧图，第 16 帧全部为新图。60 Hz 下约 0.27 秒完成。首张显示直接完整呈现，同一逻辑图片更换 bank 不触发转场。分界只在视频读帧请求边界更新；OSD 和运行时长继续在图像之后叠加，状态文字保持清晰。图片琶音和序号在首个混合帧切换，每次换图只提交一次。

四个 bank 是四段逻辑帧缓存，读侧仍只有一路 SDRAM 像素流。`SD/media_display_commit.v` 在帧边界锁存新旧 bank 和分界，`SD/media_frame_reader.v` 在每次突发开始前选取 bank：分界前读取新图、分界后读取旧图，两部分都保持原图坐标。每个输出像素只读取一次，每帧仍为 307200 个字，不增加第二路 FIFO 或 RGB 混合乘法器。30×640=19200 字，恰好按 128 字突发对齐，因此不需要在一个突发中间换 bank。本实现没有移动图像坐标，也没有进行两图 Alpha 混合。

混合帧期间显示 ACK 保留旧图的 bank 和逻辑序号，调度器同时保护目标 bank 与旧 ACK bank，防止后台预读覆盖旧图。首个全新图帧的读请求到来后，ACK 才更新到新图，允许继续切图和预读。转场期间快速按键沿用原有挂起机制，分别最多保留一次下一张、上一张请求；正在其他安全 bank 中进行的预读可以完成。

顶层 `top_tf_hdmi_audio.v` 提供编译参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `TRANSITION_MODE` | `2` | `0` 直接切换；`1` 原黑底淡入；`2` 新旧图逐行擦除 |
| `TRANSITION_FRAMES` | `16` | 转场帧数；擦除模式需整除 480，且每步像素数为 128 的整数倍，例如 8、16、24、48 |

参数需要重新编译生效，目前没有新增按键选择模式。`SD/video_fade_in.v` 保留供模式 1 使用，该模式仍有三个 8×8 RGB 乘法器；默认模式 2 不实例化它们。改动复用现有 RTL 文件，TD 工程不需要新增源文件登记。

开机预加载结束后，每当当前画面确认显示，后台补齐当前窗口：当前 4 时保留 2、3、4、5，当前 9 时保留 7、8、9、10；开头保留首四张，末尾保留末四张，不跨端预读首张。只替换窗口外且不受显示／ACK 保护的 bank，预读完成不改变画面或琶音。正常播放跨端循环仍可用，若目标不在缓存则按需读取，因此末张切首张可能等待。`THUMBNAIL_ENABLE=0` 的旧调度保留下一张预读行为；顶层启用滑动窗口。

自动轮播在预加载结束、当前画面确认显示且无待处理切图请求时计时，擦除模式下从转场完成并收到新图 ACK 后开始；后台预读期间也计时，3 秒后请求下一张。若下一张尚未读完，保持旧画面，读完后再切换；快速连按也可能等待。后台预读期间可立即请求切到其他已缓存图片，未缓存的请求等待正在进行的读取结束后处理。加载、转场或等待显示确认期间，快速按键分别最多挂起一次下一张和上一张请求，不累计无限次切图。

### 预缓存改动前备份的卡顿不足

本地 Git 备份提交 `bbf7527`（分支 `codex/multi-bmp-cache`）仅在开机时预加载前四张，显示当前图片期间不会继续预读下一张。用户上板观察到前四张切换流畅，从第五张开始切图有明显等待：按键后才读取整张 BMP、解码并写入 SDRAM，期间保持旧画面。旧图片被缓存替换后，再次切到它也需重新读取；停留时间再长也不会提前准备下一张。

读入新图片期间共用的 SD 通道无法持续补充 PCM，约 85 ms 音频缓冲耗尽后输出静音，因此会同时听到音频卡顿。当前切图请求还会暂时关闭 PCM 读卡许可，即使目标图片已经缓存。此备份保留这些不足，后续增加后台预缓存时需同时评估音频共享读卡通道，不能仅把声音卡顿提前到图片停留期间。

屏幕状态栏使用两位播放序号（01～16）、自动轮播标记 A 和两位十六进制错误码（有错误时标记 E）。序号是播放列表位置，不一定等于 PIC 文件名数字。

## 音频与异常行为

图片与 PCM 使用独立的 FAT 文件流，共用 SD 扇区读取通道。新版本在完整扇区边界分配访问权：PCM 缓冲有一整个扇区的空间时优先补充音频，缓冲接近满后读取 BMP。响应只送到获得访问权的文件流，图片读取和音频补充可交替进行。后台预读不切换音频；实际显示新图片时，按文件名数字选择对应 `AUDIOn.PCM`、清空上一首缓冲并从头循环。Wipe 从新图首次进入画面的帧开始换音，不等待旧 bank 的保护确认结束。PCM 模式下缺少对应文件时静音，旧 `AUDIO.PCM` 不作为备用音频。

PCM 缓冲仍为约 85 ms；预缓存需要真实读卡时间，不能保证任意快速切图都无等待。TF 卡单次读取延迟过长、持续带宽不足或板上时序问题仍可能导致声音短暂静音。上一张若已被替换仍需要按需读取。图片加载超过约 5 秒会报超时，不通过加大缓存或放宽超时来掩盖读卡故障。

图片琶音继续使用原有四种旋律，随播放列表序号循环选择。KEY3 切换到琶音时暂停 PCM 样本消耗；未换图则切回继续原位置。若期间实际换图，切回播放新图片对应音频的开头。上电默认仍为琶音模式，短按 KEY3 进入逐图 PCM 模式；缺文件静音的规则适用于 PCM 模式。

图片读取／解码错误或约 5 秒加载超时（错误码 E0）时，保留已有画面并停止再次加载未缓存图片，避免复用未完成的写事务；仍可切到缓存中已有的有效图片。修复卡中文件后按 KEY1 复位重新尝试。

### 2026-10-20：第八张后回到第一张的排查

这张卡的根目录首扇区最后一项为 PIC9，第二扇区第一项为 PIC10。将真实引导和目录扇区重放到当前扫描器后，识别图片掩码为 `03FF`、音频掩码为 `0003`，全部 10 张识别成功。另加 16 组图片／音频交错目录测试，在每簇 1、2、8、64 扇区时均能跨扇区／簇识别全部 16 组。这些是功能仿真，不能证明板上扫描正确，也尚未确定实机回归根因。

新增串口诊断在原 `H` 字段后追加 `M` 和 `U`，完整报文由 126 字节增为 138 字节。`M` 为 16 位图片有效掩码，最低位对应 PIC1；`U` 为调度器锁存的图片数量，两者均用十六进制显示。旧 `F` 仅包含低 4 位，不能用它判断总共扫描了几张。复位扫描完成后，这张 10 图卡应为 `M=03FF U=0A`；`M=00FF U=08` 表示只识别前八张，`M=03FF U=08` 则需检查扫描结果向调度器的传递。若两项均正确但仍循环八张，应继续核对实际切图日志。新增字段只用于观察，不改变播放控制。

COM11 在逐图 PCM 实机版本上已读取到稳定日志 `E=00 F=5 J=03 K=0000032A`，其中 F 表示前四个槽只有 PIC1、PIC3 被标记；第三个播放资源首簇 810 对应卡内 PIC5。这与电脑读取到的完整目录不同，尚需复位及新版完整掩码确认，不能当成八张限制的最终原因。22:33 诊断版已构建成功，仍使用 `hdmi_image_pcm_audio.bit`；最新校验值及资源／时序结果见 [PCM 音频说明](PCM音频播放.md)。

为此增加只读 `O` 字段，报文总长 199 字节。`O` 为 40 位十六进制，从左至右依次为：音频文件有效掩码（4 位）、控制标志（4 位）、当前图片播放索引／查表文件槽（各 1 位，均从 0 开始）、PCM 错误码（2 位）、所选文件首簇（8 位）、文件字节数（8 位）、已消耗样本数（8 位）、FIFO 当前样本（4 位）。控制标志 bit15 至 bit0 依次为读卡许可、文件已选中、音频运行、已尝试启动、换音状态（3 位）、已接收提交、提交 ACK、同步后的提交、FIFO 清空请求、清空 ACK、音频活动、样本有效、样本 ready、溢出。读卡许可不是 KEY3 音源模式；样本计数与样本来自像素域，仅用于低频趋势观察，不保证跨域多位快照原子性，也不能单凭某次样本为零认定文件静音。该字段不参与业务控制，不宣称修复 PCM 无声。
