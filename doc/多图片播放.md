# 多 BMP 图片播放

## 当前功能（2026-10-13）

图片资源由 4 张扩展为最多 **16 张**，识别 FAT32 卡根目录的 `PIC1.BMP`～`PIC16.BMP`。SDRAM 仍使用四个 bank 缓存：先加载前四张，随后在显示当前图片时后台预缓存下一张。保留 PCM 循环、图片琶音、手动切图和自动轮播。

这是有限的 16 张资源表，超过 `PIC16.BMP` 的文件不会加入播放列表。图片必须是 640×480、24 位、无压缩 BI_RGB、正高度的 BMP，不支持 32 位或压缩 BMP。

## 卡中内容与准备方法

卡使用 FAT32，文件直接放在根目录，例如：

```text
E:\
  PIC1.BMP
  PIC2.BMP
  ...
  PIC16.BMP
  AUDIO.PCM       （可选）
```

按 PIC 文件名的数字顺序播放，允许缺号。例如存在 `PIC1.BMP`、`PIC5.BMP`、`PIC10.BMP`、`PIC16.BMP` 时，播放列表为这四张，屏幕序号显示为 01～04。根目录可以跨簇，扫描器沿 FAT 链扫描最多 1024 个根目录簇；媒体文件数据也可以分散在不同簇中，无需连续存储。

在工程根目录执行：

```powershell
python -m pip install Pillow
python doc/convert/convert_images_to_bmp.py
# 将图片放入 doc/convert/input_images，再执行一次转换
python doc/convert/convert_images_to_bmp.py
python doc/convert/sync_to_sd.py E:
```

请将 `E:` 改为实际 TF 卡盘符。同步默认最多 16 张，保留卡中的 `AUDIO.PCM` 和其他文件，只更新 `PIC1.BMP`～`PIC16.BMP`。源图片按文件名排序，推荐使用两位前缀固定顺序。同步后安全弹出卡，插入板卡并按 KEY1 复位。详细参数见 [转换工具说明](convert/README.md)，音频准备见 [PCM 音频播放](PCM音频播放.md)。

## 按键

| 实体按键 | 操作 | 功能 |
| --- | --- | --- |
| KEY1 | 按下 | 复位并重新扫描卡 |
| KEY2 | 按下再松开 | 下一张，末张回到首张 |
| KEY3 | 短按 | PCM／图片琶音切换 |
| KEY4 | 短按再松开 | 开启／关闭自动轮播 |
| KEY4 | 长按约 1 秒 | 上一张，首张回到末张 |

切到已缓存的图片无需再次读卡；切到未缓存的图片时，先保留旧画面，读取、解码并写入新的 bank，再在帧边界切换。文件读取和 SDRAM 整帧写入均完成后才允许显示，显示端返回确认后才允许复用旧 bank，以避免覆盖仍在显示的画面。

开机预加载结束后，每当当前画面确认显示，检查播放列表中的下一张是否已缓存；若未缓存，选择一个安全的 bank 后台读取。预读完成只标记缓存有效，不改变当前画面或琶音。第五张会在显示第四张时预读，第六张会在显示第五张时预读；末张显示时预读首张，允许缺号。

自动轮播在预加载结束、当前画面确认显示且无待处理切图请求时计时，后台预读期间也计时，约 1 秒后请求下一张。若下一张尚未读完，保持旧画面，读完后再切换；快速连按也可能等待。后台预读期间可立即请求切到其他已缓存图片，未缓存的请求等待正在进行的读取结束后处理。加载或等待显示确认期间，快速按键分别最多挂起一次下一张和上一张请求，不累计无限次切图。

### 预缓存改动前备份的卡顿不足

本地 Git 备份提交 `bbf7527`（分支 `codex/multi-bmp-cache`）仅在开机时预加载前四张，显示当前图片期间不会继续预读下一张。用户上板观察到前四张切换流畅，从第五张开始切图有明显等待：按键后才读取整张 BMP、解码并写入 SDRAM，期间保持旧画面。旧图片被缓存替换后，再次切到它也需重新读取；停留时间再长也不会提前准备下一张。

读入新图片期间共用的 SD 通道无法持续补充 PCM，约 85 ms 音频缓冲耗尽后输出静音，因此会同时听到音频卡顿。当前切图请求还会暂时关闭 PCM 读卡许可，即使目标图片已经缓存。此备份保留这些不足，后续增加后台预缓存时需同时评估音频共享读卡通道，不能仅把声音卡顿提前到图片停留期间。

屏幕状态栏使用两位播放序号（01～16）、自动轮播标记 A 和两位十六进制错误码（有错误时标记 E）。序号是播放列表位置，不一定等于 PIC 文件名数字。

## 音频与异常行为

图片与 PCM 使用独立的 FAT 文件流，共用 SD 扇区读取通道。新版本在完整扇区边界分配访问权：PCM 缓冲有一整个扇区的空间时优先补充音频，缓冲接近满后读取 BMP。响应只送到获得访问权的文件流，图片读取和音频补充可交替进行。切到已缓存图片不再关闭 PCM 读卡许可。正常 PCM 文件结束仍从首簇循环播放，不因换图自动切成琶音。

PCM 缓冲仍为约 85 ms；预缓存需要真实读卡时间，不能保证任意快速切图都无等待。TF 卡单次读取延迟过长、持续带宽不足或板上时序问题仍可能导致声音短暂静音。上一张若已被替换仍需要按需读取。图片加载超过约 5 秒会报超时，不通过加大缓存或放宽超时来掩盖读卡故障。

图片琶音继续使用原有四种旋律，随播放列表序号循环选择。KEY3 切换到琶音时暂停 PCM 样本消耗，切回继续原位置。

图片读取／解码错误或约 5 秒加载超时（错误码 E0）时，保留已有画面并停止再次加载未缓存图片，避免复用未完成的写事务；仍可切到缓存中已有的有效图片。修复卡中文件后按 KEY1 复位重新尝试。
