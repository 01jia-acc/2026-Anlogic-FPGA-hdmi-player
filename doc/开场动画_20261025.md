## 板上效果

从 PIC1 第一幅有效显示后的帧边界开始计时，以480帧为一轮，当前帧率下约8秒：

| 时间（约） | 画面 |
| --- | --- |
| 0–1秒 | 背景、金色横线展开、底部进度条 |
| 1–2秒 | 32×32标题“文创视界”向右滑入 |
| 2秒 | 出现“FPGA 多媒体展示” |
| 3秒 | 出现“商品总览 / 工艺介绍” |
| 4秒 | 出现“图片浏览 / 缩放选择” |
| 5秒 | 出现“48 kHz 音频 / 字幕” |
| 6.5秒 | 出现“让文创细节被看见” |
| 8秒及以后 | 定格在最后一帧，保留全部文字、金色横线和完成的进度条 |

开场期间隐藏普通状态文字、时间、音频波形和字幕，保持背景干净。音频通道不改动，48kHz测试音仍通过现有开关选择。没有改成从 PIC2 开始，也没有跳过 PIC1。

每次切换回 PIC1 均从头播放。播放完成后只保持最后一帧，不自动循环；仍隐藏普通状态、时间、波形和滚动字幕，避免覆盖演示文案。切到其他图片或进入缩略图会退出并清零计时，再回到 PIC1 时重播。系统复位也会重新播放。正常按键和音频操作不被锁住。

## 实现与资源

`scrolling_subtitle.v` 中的 `opening_animation` 负责帧计时与文字布局，复用同一实例的同步字体 ROM。原有字库容量仍为4096×16位（65536位），新增23个汉字只占用原来空闲的字符槽；原有字符编号全部保留，AUDIO4字幕数据不变。

新增 `opening_text_rom` 为256×8位，预期使用1块BRAM9K。若原工程58/64 BRAM，则预期为59/64；具体以TD报告为准。没有新增帧缓存、SDRAM带宽、DSP或PLL；9位帧计数器和布局/颜色选择逻辑会占用少量寄存器、LUT/MSlice，尚未综合，不能给出实际MSlice数。

RGB、DE、VS仍沿用原字幕的两拍流水线，开场不增加视频延迟。本次复用原9位帧计数器，在479处饱和保持，并移除原一次性标志，不新增字体、帧缓存或DSP。未运行TD综合、布局布线或位流生成；目前仅完成ModelSim和主机侧验证，板上显示与最终资源/时序需编译后确认。

## 修改文案与重新生成

文案在 `assets/opening.txt`，六行分别对应上表的六段文字。RTL中的长度、位置和时间需与文案同步调整。2026-10-27 加入图5、图6字幕后字库已扩为9位编号、429槽，开场文字与三段SRT合并成共享ROM；上文256槽及独立开场ROM资源为最初版本记录，最新估算见 [图5图6配音同步字幕](图5图6配音同步字幕_20261027.md)。

保留现有字符编号并生成开场文字ROM：

```powershell
python scripts/generate_subtitle_font.py --preserve-map src/user_source/hdl_source/SD/subtitle_font.v --opening assets/opening.txt --extra assets/AUDIO5.txt --extra assets/AUDIO6.txt
python scripts/generate_file_subtitles.py --card F:\
```

此版本生成字体时需要保留 `--opening`，否则不会生成开场文字模块。

更换背景并备份卡中原PIC1：

```powershell
python scripts/prepare_opening.py <背景图片路径> --card F:\
```

只生成本地BMP及预览时省略 `--card`。
