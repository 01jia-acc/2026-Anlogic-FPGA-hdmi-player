## 实现及资源

`top_tf_hdmi_audio.v` 按实际PCM文件编号2～10选择轨道0～8，仍等待图片提交与音频提交ACK匹配。时间轴由实际PCM `ready && valid` 样本推进；暂停、欠载、切到测试音均不推进计数；返回本图或直接切换字幕轨道重新计数。每段按自身精确样本总数循环，不按帧率或文件预读完成时间估算。字幕句子在帧边界更新，保持现有两拍字体/RGB同步流水线；缩略图模式隐藏字幕。

九段正文共628字；开场六行按32字槽位存储，共192字位，合计820字位，装进原有1024×9共享文字ROM，没有按九张图分别分配256字缓存。字体重新编号并同步重编所有字幕及开场：95个ASCII和300种非ASCII，共395个槽位；旧版429槽位。UART仍支持当前字库里的中文、完整可打印ASCII及缺字问号，原来的逐拍Unicode查找保留。

字体物理数组由4096+2048+1024行减为4096+2048+512行，每行16位。按此前TD映射规则，预计字体由14块BRAM降为13块，全工程由64块降为约63块；共享文字和UART缓存保持原规模。九轨元数据与轨道选择有所增加，不能凭点阵字节数保证MSlice一定减少或满足4900。未运行TD综合、布局布线或生成位流，最终资源和时序以本次源码重新构建的报告为准。

这批内容可共用更小的静态字库，因此本次不增加卡上字库加载、扇区仲裁或SRT解析硬件。卡上“字幕”文件夹可以保留，FPGA只按原流程读取根目录BMP和PCM；TXT/SRT由电脑端脚本编译进位流，不是切图时动态读取。后续修改卡中文字后，需要重新生成和构建。若未来文案超出字库或文字ROM容量，生成器会报错，再采用每图动态字体包方案。

## 更新素材

在工程根目录执行：

```powershell
python scripts/generate_product_subtitles.py --card F:/
```

脚本优先读取 `字幕/AUDIO2.srt`～`字幕/AUDIO10.srt` 和同名TXT，找不到时读取根目录。检查图片格式、PCM长度、字幕时间/全文/字体与文字容量，然后保存本次素材到 `assets/product_20261027`，生成字体及共享字幕RTL。`manifest.json` 保存十张图片及PCM的SHA256和样本数，后续可用 `python scripts/generate_file_subtitles.py --card F:/` 校验卡上的图片/音频是否仍匹配。完整导入命令才会更新字幕源文件；不要用旧图4～6生成步骤覆盖本版数据。

本次没有删除、移动或覆盖TF卡上的任何文件，不需要将字幕移到根目录。生成器整体重排字体编号，不能混用旧的开场/字幕ROM和新字库。

## 验证及上板

主机测试独立核对27句SRT时间、文字编号及所有字体像素。ModelSim逐轨覆盖九段各两次完整循环、每句起止边界、暂停/欠载、预览隐藏、重新进入、连续轨道切换，以及每段首句640×480整帧RGB/DE/VS对齐；开场动画定格及重入、全部6656行字体跨bank访问、全BMP Unicode查找、真实UART输入也通过。十图缓存、四格窗口、拨码及顶层编译回归通过。

在TD打开原工程完整重新构建，查看MSlice、BRAM和时序后下载新位流；旧位流仍显示旧字幕。SW3拨到PCM，逐张确认图2～10播放对应新讲解并显示三句字幕；关闭SW3切到原测试音时隐藏讲解字幕。重点检查图5/10的800×800缩放、图9→10→1、直接选择缩略图、重新进入图片及每段循环后首句是否匹配。仿真通过不替代上板实测。
